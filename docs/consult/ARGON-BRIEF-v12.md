## 一、這一輪做了什麼

### 2.4 但：4 個候選全部被硬過濾淘汰

```
cand1 淘汰  CV=0.463  cvRatio=0.79  coverage=0.60
cand2 淘汰  CV=0.465  cvRatio=0.79  coverage=0.80
cand3 淘汰  CV=0.596  cvRatio=1.01  coverage=0.80
cand4 淘汰  CV=0.591  cvRatio=1.01  coverage=1.00  copy=0.86
```

最終走的是 `bandFallback`（降級交付），不是正常擇優。

### 2.5 根因：兩顆新引擎都不適合「已有人類底子」的文檔

E2 原稿的 `gen` 已經是 **0.036**，本來就沒什麼 AI 味：

| 引擎 | 行為 | 後果 |
|---|---|---|
| **routeb** | 判定「已經像人寫的」→ **原樣返回** | copy rate 0.79–0.86，撞 `maxCopyRate: 0.6` |
| **routea** | 願意改寫，但**會丟引用** | `drops citation (Colchero et al., 2017)` → coverage 不足 |

這正是我們在串聯實驗裡發現的「條件式改寫器」行為的第二次確認。

## 四、請你回答的問題

### 架構

**Q1. 並聯池對 S1/S2 的負效果，路由該怎麼設計？**
實測：E2（gen 0.036）走並聯池 → 全部候選淘汰 → 降級交付。
我們的判斷是「10.0 並聯池只適用 S4」，S1/S2 該走 9.0 的保守編輯。
但具體分流條件該用什麼？目前 `register.py` 有四個語域特徵，
但「gen ≤ 0.10 且 CV ≥ 0.50 → 保守路徑」這個條件與 register 的分類是兩個維度，
該怎麼組合？

**Q2. `maxCopyRate: 0.6` 這個閾值合理嗎？**
routeb 對人味文本原樣返回，copy rate 必然高。這是該：
(a) 放寬閾值（接受少改）
(b) 換引擎（找願意改的）
(c) 在路由層直接跳過（本就不該改）
我們傾向 (c)，但想聽你的判斷。

**Q3. 查重從 6% 升到 18%，是否管線某一步引入了更多通用表達？**
- 上次（B/A/B/A 裸稿，未過管線）：查重 **6%**
- 這次（走完整管線）：查重 **18%**（Internet 10% + Publications 8%）

管線中間有 similarityPolish（查重打磨，重生 stock 句）、mechanicalPolish、
LT 層、字數預算。理論上應該降查重，實際反而升。
可能原因：(a) 管線把句子改得更「標準」；(b) 這次文檔本身引用密度高；(c) 樣本差異。
你覺得該怎麼定位？

### 策略

**Q4. 0% AI 是偶然還是可複現？**
這次是單次結果。上次 B/A/B/A 組合是 `<20%`（不顯示具體值）。
同一個引擎族、不同的管線路徑，結果差這麼多——
你認為「走完整管線」是否真的比「裸稿組合」更好？還是只是抽樣方差？

**Q5. 字數膨脹仍未閉合，wordBudget 該用刪除還是壓縮？**
實測：僅 lengthPenalty → 1.295；加 lengthConverge → 1.204；目標 1.12。
候選池整體膨脹時選擇無法解決。管線有 `applyWordBudget`（刪除優先），
但刪除可能丟內容。你建議的方案？

**Q6. 新族膝點該怎麼標定最省碼？**
目前只有一個錨點（CV 0.465 → <20%）和這次的（CV 0.558 → 0%）。
要找出膝點，最少需要幾個點？該選什麼樣的候選稿去測？

0% AI / 18% 查重 / 12.7 分鐘全自動 / 0 人工介入。
