# 07 — 微调双线：从「调管线」转向「换心脏」（2026-10-27 – 29）

## 为什么转向微调

9.0 的结论很明确：**管线是节奏放大器，引擎才是天花板。**

所以下一步不是继续加手术室，而是换心脏。

但这个决定不是一次做完的，中间经历了几轮反复：

1. 先试「换更大的通用模型」（Qwen 27B）——能跑，但语域不对
2. 再试「微调现有 hz 12B」——发现它是续写模型，指令能力受限
3. 最后决定：**训两个专用模型，各管一个语域**

## 两条线的定位

| | 路线 A | 路线 B |
|---|---|---|
| 基座 | `Qwen/Qwen3.5-9B-Base` | `jialinyyzz/humanizer`（Gemma 4 12B 续写） |
| 数据 | 3,085 对（714 PELIC 快照 + 2,371 新增） | 2,145 对（NUCLE 2,320 修 356 + anchor 19 + passing 2） |
| 目标语域 | 大陆/亚洲学生英文（L2） | 学术正式语体 |
| 训练 | LoRA r=32，fp16，seq 640，3 epochs | QLoRA 4-bit nf4，seq 1280，2 epochs |
| 产物 | `routea-qwen35-9b`（Q5_K_M 6.47GB） | `routeb-humanizer12b`（Q5_K_M 8.0GB） |

## 路线 A：数据工程的三次迭代

### 第一次：714 对试水

从 gist 拉的 `pairs_snapshot_714.jsonl`（AI 抛光版 → PELIC 真人段落），
Colab L4 跑了 40 分钟。

**问题**：`save_strategy='no'`，没存 loss 曲线。只能靠生成样本判断。

### 第二次：扩到 3,085 对

PELIC 完整语料有 46,204 篇，按 level 4–5、段长 60–220 词过滤，
抽出 2,600 个单元素材。

AI 侧生成经历了一次重大调整：

| 尝试 | 结果 |
|---|---|
| 混合 DeepSeek + Gemini + Claude + Qwen | 中轉站 5 并发上限，两条产线互相卡死 |
| 全走智谱官方 `glm-4-air` | 5 worker，280 笔/分钟，10 分钟跑完 2,370 对 |

**关键教训**：`glm-5.3-flash` 官方版「始终思考」，8,000 tokens 全烧在 reasoning 上，
正文空白。必须降到 `glm-4-air`（不思考、长段落比例保持 1.16）。

### 第三次：+356 对抢救

路线 B 的质检发现两个 bug：

1. `truncated` 要求以 `.!?` 结尾，但学术段落常以参考文献 URL 结尾（603 个受影响）
2. `missing_number` 直接比数字串，`45%` vs `forty-five percent` 被判遗失（671 个受影响）

修正后救回 **356 对**，路线 B 从 1,789 涨到 2,145。

**这正是 9.0 第 22 課的复现：评估器自己也会误报。**

## 路线 B：一次几乎归零的教训

第一次在 A100 上跑，三小时后发现：

```
格 ⑥ → OSError: File `train_sft.py` not found
格 ⑦ → zip error: Nothing to do
```

runtime 被回收清空了 `/content`，训练根本没启动。

**修复清单**（后来写进所有训练脚本）：
1. fail-fast 断言：数据行数不够就 1 秒报错，不浪费下载模型的时间
2. `save_strategy='steps'`，每 50 步落盘
3. 单脚本一气呵成（训练+合并+打包+下载），不拆成多个手动单元格
4. 训练期间保持分页开启

## 评估：为什么不能只看训练 loss

两条线都没有可靠的 loss 曲线（A 没存、B 的日志被回收）。

所以评估必须靠**外部指标**。建立了一个 32 段评估集：

```
in-domain  20 段：PELIC 学生段落（训练时未见过）
OOD        12 段：NUCLE 带引用的学术段落
```

五个指标：`dist`（与真人目标的编辑距离）、`cv`（句长变异）、`ratio`（字数比）、
`ai_mk`（LLM 标记词密度）、`contr`（缩写率）。

### 路线 A 的实测

| 语域 | 引擎 | dist | cv | ai_mk |
|---|---|---|---|---|
| in-domain | AI 草稿 | 0.732 | 0.281 | 0.48 |
| in-domain | **tuned-A** | **0.687** | **0.344** | **0.35** |
| OOD NUCLE | AI 草稿 | 0.346 | 0.451 | 0.76 |
| OOD NUCLE | tuned-A | 0.405 | 0.441 | 0.61 |

**in-domain 13/20 段距离改善；OOD 反而变差。**

原因是 A 的任务是「写得更像学生」，而 NUCLE 的目标是正式学术文——
把 C1 拉到 B1 自然「变差」（以 dist 衡量）。这是目标语域冲突，不是失败。

### 路线 B 的实测

| 语域 | 引擎 | dist | cv | ai_mk |
|---|---|---|---|---|
| in-domain | AI 草稿 | 0.732 | 0.281 | 0.48 |
| in-domain | **tuned-B** | 0.740 | **0.413** | **0.16** |
| OOD NUCLE | AI 草稿 | 0.346 | 0.451 | 0.76 |
| OOD NUCLE | tuned-B | 0.351 | **0.465** | **0.26** |

**B 把 ai_mk 从 0.76 压到 0.26（真人 0.19），CV 拉到 0.465（真人 0.442）。**

## 两条线的能力画像

| 指标 | 路线 A | 路线 B |
|---|---|---|
| dist（贴近目标文字） | **0.687（-0.045）** | 0.740（+0.008） |
| cv（句长节奏） | 0.344 | **0.413** |
| ai_mk（LLM 标记词） | 0.35 | **0.16** |
| OOD 泛化 | 距离变差 | 距离持平、ai_mk 0.76→0.26 |

**A = 学生语域模仿器；B = 去 AI 腔 + 节奏重建器。**

两者的优势互补——这直接决定了 10.0 的并联架构。

## 这一阶段的教训

1. 数据生成的瓶颈是多家族覆盖与并发限制，不是模型能力。
2. 质检规则自己会误判，必须定期回审被拒样本（救回 20%）。
3. 评估必须用外部指标——训练 loss 既不可靠也常常没人存。
4. **一个模型只能覆盖一个语域**，这是并联而非串联的根本原因。
