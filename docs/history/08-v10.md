## 实验一：串联顺序（A → B vs B → A）

### 动机

两颗模型能力互补，最自然的想法是串起来用。

### 实测（4 段 in-domain）

| 条件 | dist | cv | ratio | ai_mk | contr |
|---|---|---|---|---|---|
| AI 原始稿 | 0.865 | 0.279 | 1.14 | 0.23 | 0.19 |
| A 单跑 | **0.781** | 0.418 | 1.19 | 0.20 | 0.19 |
| B 单跑 | 0.891 | 0.372 | 1.12 | **0.00** | 0.92 |
| B → A | 0.889 | 0.350 | 1.14 | 0.00 | 1.11 |
| A → B | 0.802 | **0.450** | 1.20 | 0.20 | 0.19 |

A→B 的 ai_mk 完全没降（还是 0.20），说明 B 没干活。

### 回聲测试：为什么没干活

比较「输入」与「第二颗模型输出」的编辑距离：

| 顺序 | 相似度 | 结论 |
|---|---|---|
| A → B（B 对 A 的输出） | lev 0.000 / 0.068 / 0.078 / 0.085 | **B 几乎原样照抄** |
| B → A（A 对 B 的输出） | lev 0.035 / 0.151 / 0.153 / 0.220 | A 只做小幅改动 |

**两颗模型都是「条件式改写器」**：只在输入看起来像训练输入时才动手。

- B 的训练输入是「AI 腔草稿」，遇到 A 已改写成的人味文本 → 判定无需处理 → 原样返回
- A 的训练输入也是「AI 腔草稿」，遇到 B 的带缩写输出 → 只做局部词替换

### 结论

**串聯无效，必须并联。** 这推翻了「A→B 会互相抵消」与「B→A 能互补」两种说法——
真实原因不是抵消，是第二颗模型拒绝工作。

## 实验二：D1 结构重排器的三次失败

顾问蓝图的核心假设是「plan 层能补 CV」。试了三种实现。

### 方式一：prompt 直接下句长配额

对 `highAI-0983` 第 2 段（168 词，原 CV 0.297）下达明确配额：

| 模型 | 要求 | 实际 | 实际 CV |
|---|---|---|---|
| B | 6 句 [47,12,37,15,40,17] | **8 句** [27,25,18,15,31,33,40,34] | 0.282（更差） |
| B | 7 句 [50,10,40,13,30,12,12] | 7 句但**均匀** | 0.179 |
| A | 6 句 [47,12,37,15,40,17] | **8 句** | 0.248 |
| A | 7 句 [50,10,40,13,30,12,12] | **8 句** | 0.297 |

**两颗模型都完全无视句数与句长指令。**

这与官方文档一致：hz/humanizer 的提示词必须逐字一致，额外指令会破坏训练分布。

### 方式二：机械拆併句（不改词，只改标点）

对 B 的输出（全篇 CV 0.450）套「拆最长句 → 併最短相邻句」：

| 段 | 原 CV | 处理后 CV |
|---|---|---|
| 0 | 0.370 | **0.192** |
| 1 | 0.464 | **0.278** |
| 2 | 0.514 | **0.275** |
| 全篇 | **0.450** | **0.270** |

**CV 不升反降 40%。**

数学上的必然：词数与内容固定时
- 拆一个 30 词长句 → 两个 15 词句，离散度**下降**
- 併两个短句 → 一个中等句，**消灭极值**

要提高 CV 必须让分布更极端（几个超长句 + 一堆极短句），
那需要**重新分配内容**，不是机械改标点能做到的。

### 方式三：并联择优穷举

对 `highAI-0983` 的 4 个正文段，用 A 和 B 各生成一遍，
然后穷举 **3⁴ = 81 种段落组合**，找全篇 CV 最高值：

| 组合 | CV | ai_mk |
|---|---|---|
| B 全部改写 | 0.450 | 0.24 |
| A 全部改写 | 0.367 | 0.00 |
| **最高组合 B/A/B/A** | **0.465** | 0.13 |
| 目标（旧族门槛） | 0.540 | — |

**没有任何组合达到 0.54。**

### 另一个发现：B 在长段落上严重膨胀

| 段 | 原词数 | B 输出 | B 比值 |
|---|---|---|---|
| 0 | 168 | 216 | **1.29** |
| 1 | 180 | 219 | **1.22** |
| 2 | 189 | 257 | **1.36** |
| 3 | 124 | 132 | 1.06 |

会在管线的 `validateUnit`（1.15 闸）直接被拦。

## 转折点：花一个真码问清楚

三次失败后的关键判断：

> `CV ≥ 0.54` 是 **旧 hz-12B 引擎族**的校准结果。
> 新引擎的 token 分布完全不同，凭什么沿用旧尺？

这与 L5 的教训一致：**特征阈值是引擎族特定的。**

### 送检条件

| 项目 | 内容 |
|---|---|
| 原稿 | highAI-0983（原判 **98% AI**） |
| 送检文本 | `B/A/B/A` 组合（CV 0.465，ai_mk 0.13，811 词） |
| 渠道 | turnitai.club 国际版 |

### 结果

```
AI 检测      < 20%（Turnitin 显示 *%，低于阈值不揭露具体数字）
查重         6%（Not Cited 4% + Missing Quotations 2%）
Integrity    0 flags
来源分布     Publications 4% / Internet 2% / Student Papers 0%
```

### 这个结果推翻与确立的事

**推翻**：必须把 CV 推到 0.54 才能过检测。
实际 CV 只有 0.465，仍然通过。

**确立**：
1. CV 0.54 是旧族阈值，新族门槛低约 **0.075**
2. A+B 并联择优是有效架构（不需 D1 就把 98% 压到 <20%）
3. **D1 结构重排器不需要做**——省下最大的工程块

## 实验三：质量轴审计（第三次误读的复现）

真码报告里分数满分，但把送检文本逐句读一遍，发现 **11 处读者可见的语法硬伤**：

```
make purchase（漏复数）
One of the major difference（单复数）
Physical store need（主谓不一致）
less customers（可数名词用 less）
both two channels（冗余）
he has purchased（代词单复数跳跃）
...
```

### 来源确认

这些正是 NUCLE 语料的特征——它本身是 **GEC（语法错误修正）研究用的
「真实学习者原文」数据集**。

模型忠实学到了亚洲大学生的句法微瑕。这也解释了为什么 `ai_mk 0.13` 却能拿 <20%：
**它的 token 转移概率就是一个真实学生。**

### 关键验证：修语法会不会破坏分数？

跑管线自己的 `lt_fix.py`（LanguageTool 6.8 + 便携 JRE）：

```
4 fixes applied
  fulfillment → fulfilment    ← 只是英式拼写
  flipside    → flip side      ← 也只改拼写
  behavior    → behaviour      ← 英式拼写
  less        → fewer          ← 唯一修对的语法
```

**主谓一致、冠词缺失、`both two`、代词跳跃，LanguageTool 完全没检出。覆盖率 4/15。**

自己写了 15 条针对性规则（不动句构、不改用词），修完后：

| 指标 | 修复前 | 修复后 |
|---|---|---|
| CV | 0.472 | **0.474** |
| 句数 | 39 | 39 |
| 词数 | 811 | 805 |
| ai_mk | 0.12 | **0.12** |

**15 处全修，CV 与 ai_mk 完全没动。**

结论：**质量轴可以独立修复，不会回头破坏已经拿到的分数轴。**

## 10.0 架构定案

综合以上全部实测：

```text
原稿
 ↓
L0 四语域特征路由（p1_rate / cite_num_rate / nom_rate / mean_para_words）
 ↓
L2 并联生成（B×3 + A×2，批次调度，一份文档切一次模型）
 ↓
L2.5 确定性修复（L2 语法规則库 → 缩写展开 → LT → 字数预算）
 ↓
L3 双轨验收（分数轴 + 质量轴，两轴都过才交付）
 ↓
交付
```

### 四个与 9.0 的关键差异

| | 9.0 | 10.0 |
|---|---|---|
| 引擎 | 单一 hz 12B | A+B 并联 |
| 结构重排 | 依赖 X 重组 + grind | **取消**（三种实现全失败） |
| CV 门槛 | 0.54 | **0.42**（新族实测） |
| 验收 | 分数轴 | **双轨** |

## 这一阶段的教训

1. **串联不成立的前提是「两颗模型都会动手」**——实际情况是条件式触发。
2. **CV 阈值必须按引擎族重新标定**，旧尺量新族会得出错误结论。
3. **一个真码可以省掉数周工程**——先验证假设再投入实现。
4. **质量轴与分数轴独立**，修语法不破坏分数（前提：只修表层）。
5. **LanguageTool 覆盖不足**，不能把质量保证寄托在它身上。
6. 第三次误读的复现：真码通过 ≠ 可交付，必须同时读文本。
