## 閱讀路徑

- **新接手的人**：`history/README.md`（一頁時間線）→ `WORKFLOW.md` 的「現行管線」→ 對應版本的附錄 A 條目
- **要跑一單**：`WORKFLOW.md` 第 3 章（五分鐘上手）＋第 12.0 節（現行驗收紀律）
- **要改代碼**：`WORKFLOW-10.0.md`（架構約束）→ `WORKFLOW.md` 附錄 A 最近三個版本（避免重犯）
- **要判斷能不能接單**：`WORKFLOW.md` 的「能力邊界」表 ＋ `pipeline/precheck.mjs`

## 維護規則

1. 文檔改動與代碼改動**同一 commit**（2026-10-28 的勘誤就是因為文檔落後於代碼而發生）。
2. 數字必須可追溯：分數寫明校準點號、渠道、日期。
3. 每個版本一條記錄，永不刪除；發現舊記錄有錯，改該條並在「文件狀態與勘誤」登記。
4. **校準點號 ≠ 版本號**：點 = 數據（1–23），版本 = 軟件里程碑。
5. 新校準點 → 同時更新 `calibration.json`、`WORKFLOW.md` 附錄 B、`history/README.md` 的數據資產段。
